# 14 · 项目实施路线图

> 面向实际落地的分期路线、MVP 边界、成本测算与建议。
> 版本：1.0 ｜ 依赖：全部板块

---

## 1. 总原则

不一次性全量上线。按"垂直切片"推进：先跑通一条最短但可用的主链路，验证一致性与成本，再逐期补强。把本蓝图视为**架构愿景**，把本文件的分期视为**首版实现范围**。

## 2. 分期里程碑

### 阶段 0：设计定版（本批次）
- 完成本套板块文档（`00`–`14`），冻结领域模型（事实结构、INV、管线 DAG、token 预算）。

### 阶段 1：MVP —— 一条能写的短主链路
- 范围：四层大纲（`03`）+ 六系统真相文件基础版（`04`）+ fact 写入协议（`05` 的 ADD-only/溯源/时效）+ 章级管线（`02` 简版：仅生成→审计→章后B/C）+ 分级审计里的确定性不变量 + P/C/I 组轻量 LLM 复核（`07`）+ 基础上下文切片预算（`12`）
- **不做**：技能系统、幕/卷报告全量、回滚 Fork、向量检索。先跳过能省的成本杠杆都跳过。
- 验收：用 20–30 章短篇或中篇前 10 章跑通；一致性 Score 达阈值；单章 token 落在预算内（`12` §5）。
- 关键检验点：错误是否跨章传播可控；认知边界是否生效；token 是否收敛。

### 阶段 2：质量闭环
- 补 45 维全量审计（关键章触发）+ 双模型独立仲裁（`07`）+ 幕/卷六维报告 + 真相文件全量校验（`11`）+ 回炉修订闭环（`02`）
- 引入 Checkpoint / 时间旅行 / 定点回滚（`05` §7、`10`）
- 引入作者意图声明（`06` §3）

### 阶段 3：扩展与技能生态
- 技能制造五步流 + 技能库 + 冲突矩阵（`09`）+ 沙箱测试（`13`）
- LangGraph 编排落地（`02` §8），把暂停/复审演化为 Human-in-the-loop
- 存储升级（`12` §7），必要时引入向量检索与 SQLite fact 表

### 阶段 4：规模化与打磨
- 全量多卷创作、性能优化、读者反馈闭环（外部试读评分返回审计/技能权重）、反 AI 味标准外置化校准

## 3. MVP 边界（明确不做清单）

| 能力 | 是否 MVP | 原因 |
|------|---------|------|
| reveal_density 大纲过滤 | 是 | 防剧透核心，成本低 |
| 认知边界注入 | 是 | 成本低价值高 |
| fact ADD-only + 溯源 | 是 | 一致性根基 |
| 确定性不变量（INV） | 是 | 硬门槛，零 LLM 成本 |
| 章后管线 B/C（确定性） | 是 | 事实/索引更新 |
| 45 维全量审计 | 否 | 阶段 2，成本高 |
| 全量跨文件校验 | 否 | 阶段 2 |
| 技能系统 | 否 | 阶段 3 |
| 向量检索 | 否 | 按需，早期用结构化匹配 |
| 回滚 Fork | 否 | 阶段 2 |
| 幕/卷报告六维 | 否 | 阶段 2 |

## 4. 风险与权衡预案

1. **token 成本失控**：MVP 即按 `12` §5 预算记账，任何环节超 20% 触发告警和分级降档。
2. **审计自证**：MVP 就坚持 audit_model 独立（即使同一提供方也要不同 model 名），关键提交可人工抽检。
3. **过度工程**：所有"确定性/结构化"优先满足硬一致性，文学主观维一律保持建议性、不阻断，避免扼杀创作自由。
4. **错误跨章传播**：即使 MVP 无全量校验，靠 fact 溯源 + 章节摘要一致性自查先行兜底，阶段 2 再上全量。
5. **"能写但没魅力"**：质量底线靠审计，上限靠人工打磨 + 后续读者反馈回流，蓝图的定位是"不犯错的底座"不是"自动封神"。

## 5. 借鉴来源（落地的技术栈提示）

- 编排/可回滚：LangGraph（checkpoint、time travel、interrupt）
- 上下文/记忆：Graphiti/Mem0 模式（时效窗口、溯源、多信号检索）
- 一致性校验：Novel-OS（确定性引擎 + Guard）
- 质量把关：NovelForge/OpenNovel 的 Review 分工、LLM-as-Judge
- 超长生成：LongWriter 子任务拆解
