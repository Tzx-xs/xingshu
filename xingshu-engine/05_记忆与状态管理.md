# 05 · 记忆与状态管理机制（本项目强化板块）

> 这是相对原蓝图最重要的新增板块，解决"错误跨章节传播"与"无法回滚"两大核心痛点。
> 版本：1.0 ｜ 依赖：`04` ｜ 相关：`07`(审计)、`10`(回滚)、`11`(全量校验)

> 「精华借鉴」本节思想主要来自：Mem0（ADD-only）、Graphiti（时效窗口+溯源）、Cognee（remember/recall/forget/improve）、Zep（异步抽取）、LangGraph（Checkpoint/时间旅行/Fork）、ContextCraft（压缩覆盖率+版本回滚）。

---

## 1. 目标

真相文件是不断增长的事实库。若不加以约束，单个错误事实会借由后续生成**跨章节传播**。本节确立写入、时效、溯源、检索、回滚的标准，使事实库：
- 可累积（不因覆盖丢失历史）
- 可过期（能表达"曾经正确、现已改变"）
- 可溯源（每条事实能找到来源）
- 可回滚（定位错误后能定点恢复）

## 2. 事实（Fact）的统一结构

每条写入真相文件的"事实"带统一头：

```yaml
fact:
  id: "fact_{uuid}"
  system: characters | relations | factions | locations | timeline | foreshadowing
  entity: {目标实体ID}               # 如 char_003 / loc_005
  attribute: {字段名}                # 如 psychological_state / influence
  value: {值}
  source: {来源}                      # 章节ID / 事件ID / user_manual / user_edit
  valid_from: {章号或时间戳}           # 生效点
  valid_until: null                   # 失效点（被取代时写入）
  status: active | superseded         # 有效；已被取代(保留历史)
  confidence: {0-1}                   # 置信度（用户确认=1）
  created_at: {ISO时间}
```

## 3. 写入协议（三条铁律）

1. **ADD-only 只累积，不覆盖**（借鉴 Mem0）：新增行为默认新增一条 fact；修改 = 写新 fact + 把旧 fact 的 `valid_until` 置为当前点、`status` 置 `superseded`。**绝不原地改写旧记录**。
2. **显式时效窗口**（借鉴 Graphiti）：每条 fact 必须带 `valid_from/valid_until`。允许"曾有效、现已失效"的事实保留，真相文件查询时只返回 `status=active && valid_until=null` 的记录。
3. **强制溯源**（借鉴 Graphiti Episodes）：写入方必须提供 `source`（来自哪章、哪事件、还是用户手改）。无 source 的写入禁止进入事实库。

> 与 `04`"旧记录保留不追加"衔接：这里把"保留"升级为带失效标记 + 来源 + 时效的结构化版本。

## 4. 查询 / 检索协议

「精华借鉴」多信号混合检索（Mem0 语义+BM25+实体；Graphiti 图遍历）：
- 检索某章上下文时，对 `active` 事实执行三种召回并融合：
  1. **结构化字段匹配**：`entity` 在本章出场 + `system` 命中 → 高置信
  2. **语义向量检索**：attribute/value 与当前场景语义相似
  3. **关键词/实体命中**：提及的实体名、地点、关系边
- 结果注入 Layer2 前按 `04` 的认知边界/密度过滤。
- 避免只靠单一向量相似度导致的关键事实漏检。

## 5. 四段操作 API（借鉴 Cognee）

事实库对外暴露四个操作：

| 操作 | 语义 | 用途 |
|------|------|------|
| `remember` | 写入一条带溯源/时效的 fact | 章后管线-B、用户手动设定 |
| `recall(params)` | 按多信号检索返回 active 事实 | 章节上下文注入、审计核对 |
| `forget(id, reason)` | 将事实标记 superseded/失效（逻辑删除） | 处理过时/错误/冲突事实 |
| `improve(id, patch)` | 修正并新增带 source 的新版本 | 用户修正、回滚补丁 |

> 不允许直接 delete 物理删除；一律走 `forget` 或 `superseded`，保留审计历史。

## 6. 层级记忆抽象（补充，借鉴 NovelForge/OpenTheatre）

用于控制上下文规模，与真相文件互补：

| 层 | 内容 | 用途 |
|----|------|------|
| Working Memory | 当前章场景内活跃的 fact | 本轮生成直接注入 |
| Episodic Memory | 章节摘要 + 事件序列（`ch_XXX_summary.md`） | 前 3-5 章回顾、跨章核对 |
| Semantic Memory | 长期规则类 fact（世界规则、角色特质） | 稳定注入 |

Working/Episodic/Semantic 归到同一套 fact 溯源，检索时按命中层返回。

## 7. 版本化 Checkpoint 与时间旅行（借鉴 LangGraph）

- **Checkpoint**：每次章后管线完成（或用户暂停保存）时，对整个真相文件目录打一个带时间戳的 checkpoint 快照。
- **时间旅行**：`get_state(时间点)` 可得任意历史快照；用于幕末全量校验定位"错误从哪章开始"。
- **Fork 分支探索**：从某历史 checkpoint 复制分支，验证"若此处用另一套设定"不影响当前主线，供用户试改。
- **定点回滚**：确认某章引入错误后，`restore(checkpoint, before_章)` 回退受污染范围并标注待重写章节；不销毁该段之后的其它正确写入（按 `entity/attribute` 级取舍）。
- 实现上：若用 LangGraph 编排，其每步状态快照即本机制的落地载体（见 `02` §8、`10`）。

## 8. 防膨胀与压缩

- 事实总数阈值（如 `reading` 目标），`forget` 掉长期 inactive 且有 superseded 的旧版本，压缩 `Episodic Memory` 摘要。
- 「精华借鉴」压缩后语义覆盖率校验（ContextCraft）：压缩摘要前后，对关键实体/关系做覆盖率比对，覆盖率过低则回退压缩方案或降档压缩。
- 压缩操作本身作为一条 `improve` 记入历史，支持回滚到压缩前。

## 9. 三点权衡说明

1. **自主 vs 确定**：`04/05` 的真相文件更新默认走确定性规则（章后管线-B），可审计、可回滚。开放给 LLM 自主写记忆（Letta 范式）仅限"印象/文风类"，核心事实必须走规则，避免错误自主写入。
2. **性能**：检索优先级对活跃长篇<200 事实的小规模场景用结构化匹配即可；300+ 再开启向量（视需要引入 embedding 库）。避免过早引入向量基础设施。
3. **存储**：默认 Markdown+YAML 文件即可支撑到中等规模；超过阈值（建议见 `12`）可考虑 SQLite 承载 fact 表，schema 与本节字段对齐。
