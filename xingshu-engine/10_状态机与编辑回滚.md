# 10 · 状态机 与 编辑回滚

> 定义引擎运行状态机、用户暂停-修改-复审流程、影响范围分析、以及增强的定点回滚能力。
> 版本：1.0 ｜ 依赖：`02`、`05` ｜ 相关：`07`(复审审计)、`11`(全量校验)

---

## 1. 引擎状态机

用户操作和引擎操作在时间上完全隔离：

| 状态 | 引擎行为 | 用户权限 | 切换条件 |
|------|---------|---------|---------|
| **运行中** | Pipeline 自动生成 | 只读 | 当前完整单元完成后可暂停 |
| **暂停中** | 引擎完全停止 | 可读写，自由修改 | 用户保存修改后进入复审 |
| **复审中** | 审计层针对性检查用户改动 | 只读，等待结果 | 通过→继续 / 不通过→回暂停 |
| **继续** | Pipeline 从暂停点恢复 | 只读 | 自动回到运行中 |

**核心约束**：不支持创作中途修改（须等一个完整单元写完）；暂停由用户主动发起；修改后必须复审；用户标记修改内容（系统知道改了什么）。

## 2. "完整单元"定义

| 单元 | 完成标志 | 可修改 |
|------|---------|--------|
| 全局设定 | 录入完成 | 全局设定 |
| 大纲 | 规划产出完整大纲 | 全局设定+大纲 |
| 卷纲/幕纲/章纲 | 对应生成完成 | 该纲 |
| 章正文 | 规划→收尾全流程完成 | 该章正文+章纲 |
| 幕完结 | 本幕全部章节完成 | 本幕内容+下一幕设定 |
| 卷完结 | 本卷全部幕完成 | 本卷内容+下一卷设定 |

## 3. 暂停-修改-复审流程

```
暂停指令 → 系统检查当前单元是否完成（否→"第5章正在生成，请等待"）→ 进入暂停
→ 用户自由修改（设定/角色/关系/势力/大纲/正文/伏笔/隐藏设定/作者意图声明）
→ 保存 → 系统对比差异，触发针对性复审
→ 通过→恢复引擎 / 不通过→Agent 返回问题，用户继续改
```

## 4. 复审 vs 正常审计

- **正常审计**：45 维全量（写每章后）
- **用户修改后复审**：只检查受影响维度（更快更轻量）

| 用户改了 | 复审范围 |
|---------|---------|
| 角色设定 | 人设一致、关系矩阵、社会关系网络、势力归属 |
| 世界观 | 规则一致、势力格局 |
| 正文 | 前后文衔接、伏笔引用、关系变化是否有事件驱动 |
| 伏笔 | 伏笔状态、回收逻辑 |
| 势力设定 | 势力版图一致、成员归属、势力间关系 |

## 5. 影响范围分析器

用户修改后自动分析影响范围，确定需同步/重审的数据：

| 用户修改 | 自动影响范围 | 需重新同步/审计 |
|---------|------------|----------------|
| 角色认知 | 人物卡→信息差追踪→相关章节审计→后续视角段 | 信息差记录+相关章重审 |
| 伏笔状态 | 伏笔台账→隐藏设定→convergence_point→后续章纲 | 伏笔文件+隐藏设定+后续章纲重规划 |
| 地点状态 | 地理卡→旅行矩阵→势力版图→时间线 | 地理卡+时间线重校验 |
| 章节正文 | 摘要→关键事件→人物状态→索引→文风向量 | 章后管线A/B/C重执行+索引重建 |
| 势力关系 | 势力卡→社会关系卡→人物所属势力→冲突 | 势力卡+关系卡+冲突检测 |

## 6. 定点回滚（增强：本版新增）

「精华借鉴」LangGraph Checkpoint / 时间旅行 / Fork。补足原蓝图"只追加缺少回滚"的短板（详见 `05` §7）：

| 能力 | 说明 | 使用场景 |
|------|------|---------|
| Checkpoint | 章完成/暂停保存时对真相文件打周快照 | 定位错误起点 |
| 时间旅行 get_state | 取任意历史快照 | 幕末校验定位错误从哪章开始 |
| 定点回滚 restore | 回退受污染范围，标注待重写章，保留其后的其它正确写入（按 entity/attribute 级取舍） | 修正跨章节错误传播 |
| Fork 分支探索 | 从历史点复制分支试改，不影响主线 | 用户验证"另一种设定" |

**回滚流程**：
```
发现错误（幕末校验 / 复审 / 用户自查）
  → get_state 定位引入该错误的章节 checkpoint
  → restore 到该章之前
  → 受影响后续章标记"待重写"（记入 novel_meta.progress）
  → 对受污染的 fact 按 `05` 的 superseded + source 方式修正
  → 重新执行章后管线与校验
```

## 7. 与 `05` 的衔接

所有真相文件写入均带来源与时效（`05`），所以：
- 回滚是有据可依的定点操作，而非整库重来；
- 用户手动改造成新 fact（source=user_edit），复审可追踪；
- `forget`/`superseded` 承载"过时事实失效"，`restore` 承载"错误事实回退"——两者不冲突。
