# 07 · 审计与质量系统

> 定义生成质量与一致性的把关机制：45 维审计、五级严重度、8 条叙事不变量、确定性引擎 + LLM 复核、评分。
> 版本：1.0 ｜ 依赖：`04`、`05` ｜ 相关：`11`(报告与全量校验)、`02`(回炉)

---

## 1. 审计执行方式：确定性引擎前置 + LLM 复核

「精华借鉴」基本思路来自 Novel-OS 的 Continuity Engine + Guardian，以及原蓝图"结构化检查做线索、语义判断做判定"。升级为两级：

```
审计开始
  ├─ ① 确定性不变量引擎（零 LLM，规则驱动，零误报）
  │     检测叙事不变量、结构性指标、状态机合法性
  │     └─ 产出"确定性问题清单"（可确证） + "存疑清单"（需 LLM 定夺）
  ├─ ② LLM 语义复核（只处理存疑项 + 主观维度）
  │     对结构性存疑做最终判定；对文学质量/AIGC 等主观维度评分
  │     合并为审计报告
  └─ ③ 输出：综合评分 + 问题清单 + 审计结论
```

收益：确定性引擎先行大幅降低单章 LLM 调用量和自证风险；LLM 只定夺存疑与主观项。

## 2. 45 维审计清单

### 反AI味协议 P1-P8（8维）
| 编号 | 维度 | 判定标准 |
|------|------|---------|
| P1 | 信息密度 | 每段≥2有效信息单元 |
| P2 | 感官优先 | 每场景≥3种感官描写 |
| P3 | 角色差异 | 不同角色语言风格有区分 |
| P4 | 节奏控制 | 长短句交替，避免均匀节奏 |
| P5 | 衔接自然 | 避免机械过渡词（然后/接着/于是） |
| P6 | 解释句式禁令 | 禁止"也就是说/换句话说/简单来说" |
| P7 | 展示不讲述 | 展示占比≥60% |
| P8 | 情感克制 | 直白情感词≤20% |

### 叙事宪法 C1-C6（6维）
| 编号 | 维度 | 判定标准 |
|------|------|---------|
| C1 | 事实锁定 | 与真相文件完全一致 |
| C2 | 关系锁定 | 关系状态与最新版本一致 |
| C3 | 伏笔纪律 | 无无铺垫升级、无超额揭示 |
| C4 | 禁止事项 | 不违反禁止列表 |
| C5 | 设定一致性 | 不矛盾已揭示设定 |
| C6 | 时间线一致 | 时间顺序正确无矛盾 |

### 一致性检查 I1-I8（8维）
人物行为/语言/能力边界/地理/势力/时间/物品/称呼一致性。

### 文学质量 L1-L10（10维）
对话自然度、场景沉浸感、情感真实度、叙事张力、节奏感、意象运用、主题深化、留白艺术、开头吸引力、结尾余韵。

### 技能规则 S1-S8（8维）
激活技能的每条 rule 逐条检查。

### AIGC 风控 A1-A5（5维）
机械表达、套路化结构、过度修饰、逻辑跳跃、重复表达。

## 3. 五级严重度分级

| 级别 | 定义 | 处理策略 |
|------|------|---------|
| **Blocker** | 违反不变量或硬逻辑错误 | 必须修复，阻断入库，触发回炉 |
| **Major** | 显著影响一致性或体验 | 强烈建议修复，标记技术债务通知用户 |
| **Minor** | 轻微一致性问题/小瑕疵 | 记录不阻断，幕末统一回顾 |
| **Style Hint** | 文风优化建议 | 注入提示不强制，可忽略 |
| **Creative Choice** | 可能是作者有意文学手法 | 标记为创作选择，不进修订流程 |

**分级决策流程**：违反不变量→Blocker；六系统交叉失败→Blocker/Major；文风严重/轻微偏离→Major/Minor；情感/节奏突变+确认文学手法→Creative Choice；NLP线索+LLM验证→Major/Minor；仅文风优化→Style Hint。

**Creative Choice 判定**：检测到情感/节奏异常时，判断是否含反讽/对比/欲扬先抑等手法标志 → 有→Creative Choice；无且影响一致性→Major；无且不影响→Minor。并尊重 `06` 的作者意图声明。

## 4. 8 条叙事不变量（硬约束，违反即阻断入库）

| ID | 规则 | 校验方式 |
|----|------|---------|
| INV-001 | 角色不能知道未揭示事实，除非有揭示事件 | 状态变更检查章节事件 |
| INV-002 | 同一角色不能同一时间在两地点 | 时间线×地理位置交叉 |
| INV-003 | 地点状态不能倒退，除非有修复事件 | state_changes 单调性 |
| INV-004 | 关系强度变化必须有关联事件 | 关系边变化检查事件日志 |
| INV-005 | resolved 伏笔不能再作为未解伏笔推进 | 状态机校验（resolved 终态） |
| INV-006 | retired 隐藏设定不能自动重新激活，除非用户确认 | 状态机 + 用户确认 |
| INV-007 | 索引版本不能高于正文版本，不能长期低于已提交状态 | 版本号比较 |
| INV-008 | 章后管线 A→B→C 顺序 | DAG 依赖校验 |

> 不变量检查属于确定性引擎（不依赖 LLM），是审计的第一道门槛。（借鉴 Novel-OS 的确定性校验理念）

## 5. 审计报告格式

```markdown
# 审计报告 — 第X章
## 综合评分：{0-100}
## 各维度评分  {P1-P8 / C1-C6 / I1-I8 / L1-L10 / S1-S8 / A1-A5}：pass/fail + 说明
## 问题清单   [{维度编号}] {问题} → {修复建议}
## 审计结论
- [ ] 通过（≥75，无 blocker）
- [ ] 修复后通过（60-74，或有 warning）
- [ ] 回炉重写（<60，或有 blocker）
```

## 6. 审计评分计算

| 维度组 | 维度数 | 权重 |
|--------|--------|------|
| 反AI味 P1-P8 | 8 | 25% |
| 叙事宪法 C1-C6 | 6 | 25% |
| 一致性 I1-I8 | 8 | 20% |
| 文学质量 L1-L10 | 10 | 15% |
| 技能规则 S1-S8 | 8 | 10% |
| AIGC 风控 A1-A5 | 5 | 5% |

**评分规则**：每维 pass=满分 fail=0；有 Blocker→综合<60（回炉）；有 Major 无 Blocker→上限74；仅 Minor 及以下按实得分。

## 7. 审计分级（成本控制，配合 `12` 预算）

「精华借鉴」（NovelForge Review/OpenNovel 审稿 + 控制 token）：
- **常规章**：确定性引擎 + 轻量 LLM 复核（P/C/I 这 3 组），低成本
- **关键章**（战斗/转折/伏笔交汇/高潮）：全量 45 维
- **全量校验**（幕/卷）：走 `11`，另执行跨文件交叉一致性
- 分级后 L1-L10 / A1-A5 在常规章可降为"仅标记不阻断"或抽查，降低主观维度自证噪音与成本。

## 8. 双模型独立仲裁（缓解"审计自证"）

- 建议 `audit_model` 与 `writer_model` 分开配置（`12` 的 `llm` 段）。
- 确定性引擎产出的存疑清单必须交给独立的 audit_model 复核，避免同模型既写又判。
- 对主观维度（L/A 组）保持"建议性 + 抽查"，把硬阻断只保留给确定性可证项。
