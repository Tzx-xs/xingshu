# 06 · 伏笔纪律 与 双设定体系

> 定义伏笔用法纪律、语义偷换、渐进式揭示，以及明面/隐藏双设定访问规则。
> 版本：1.0 ｜ 依赖：`03`、`04` ｜ 相关：`07`(审计)、`08`(提示词)

---

## 1. 伏笔纪律

### 1.1 语义偷换纪律
语义偷换是本引擎的核心伏笔技法——日常用语中潜藏关键概念，前期以普通含义自然出现，后期集中升级：
- 同一词汇/意象在不同阶段含义必须可追溯 —— 章后管线-A 维护概念演化链
- "偷换点"必须依赖前文铺垫，禁止无中生有的概念升级
- 节奏：大部分章节普通含义，关键节点集中升级

**审计检查规则**：演化链是否完整；偷换点是否有铺垫；是否存在无铺垫升级。

### 1.2 渐进式揭示纪律
- 设定揭示采用链式依赖：每层依赖前一层铺垫
- "长铺垫 + 密集爆发"：大部分章节给碎片，关键节点集中揭示
- 单章揭示密度由 `reveal_density` 控制，不得超额

**审计检查规则**：是否超密度；是否有铺垫；是否跳跃式揭示。

### 1.3 伏笔状态机
`planted → progressing → converging → revealed → resolved`（单向不可回退）。

## 2. 双设定体系

### 2.1 明面 vs 隐藏设定
**明面设定** — 读者和角色都知道的世界规则，早期交代，是理解剧情的基础框架。
**隐藏设定** — 只有作者（和部分角色）知道的真相，通过伏笔逐步揭示，是深层驱动力。

### 2.2 设定文件格式
```markdown
# 世界设定
## 明面设定（is_public: true）  {读者知道的规则}
## 隐藏设定（is_public: false）  {实际规则/被掩盖真相/揭示计划}
## 隐藏设定的揭示计划
- 第X章：碎片1 ｜ 第Y章：碎片2 ｜ 第Z章：集中揭示
```

### 2.3 创作时设定访问规则
- 生成阶段只注入当前章节 `reveal_density` 允许的设定
- 明面设定可自由引用；隐藏设定只注入"已揭示部分 + 本章计划揭示碎片"
- 未揭示的隐藏设定不注入生成上下文，防止提前剧透

## 3. 作者意图声明通道（借鉴 Novel-OS "This is intentional"）

战场摘要：审计层可能把"非线性叙事 / 不可靠叙述者 / 欲扬先抑 / 视角切换"误判为逻辑错误。为此提供**作者意图声明**机制：
- 用户在暂停状态（见 `10`）可为某章/某实体声明"此现象是有意为之的文学手法"
- 声明记录在真相文件中（事件类型 `author_intent`），审计遇此声明不再判 Blocker/Major，转记 Creative Choice
- 这是 `07` 五级严重度里 Creative Choice 的"可操作化"入口

## 4. 揭示计划与审计联动

- 卷纲的"隐藏设定揭示计划"定义各章应揭示的碎片（`03`）
- 揭示后，章后管线-A 更新揭示链进度；幕末全量校验核对"非揭示节点是否泄露／揭示节点是否完成"（`11`）
