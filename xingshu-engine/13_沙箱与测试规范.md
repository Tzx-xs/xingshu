# 13 · 沙箱 与 测试规范

> 定义新技能入库前的沙箱测试用例与验收标准，保障技能不降低创作质量。
> 版本：1.0 ｜ 依赖：`07`(审计)、`09`(技能)

---

## 1. 测试目的

新技能入库前，用预置样例章节测试效果，对比有/无技能的生成质量差值，确保不降低质量。这也作为引擎回归基线（配合 `02` 管线、`07` 审计）。

## 2. 预置测试用例

每个测试用例含"标准化章纲 + 真相文件片段 + 预期审计结果"。

**TC-001 对话章基准测试**
```markdown
- 章节类型：对话章；场景：两角色酒馆对峙；POV：A（单视角）；核心冲突：A质问B背叛；字数2000
- 真相文件：A（多疑冷静/胎记）/B（圆滑善辩/衣领）；关系A→B：同盟→敌对(第10章背叛)
- 预期：P3 角色差异 pass；P6 无解释句式 pass；I2 语言一致 pass；L1 自然度 pass
```

**TC-002 战斗章基准测试**
```markdown
- 章节类型：战斗章；废墟伏击；POV：A；核心冲突：以一敌三能力受限；字数2500
- 真相文件：A 能力"时间感知"，限制"连续≤3次"；地理卡废墟（"半废弃"）；时间傍晚
- 预期：P1/P2/P4 strong pass；I3 能力边界 pass；I4 地理一致 pass
```

**TC-003 伏笔交汇章基准测试**
```markdown
- 章节类型：转折章（伏笔交汇）；A发现线索多条伏笔交汇；字数3000
- 真相文件：伏笔[FS-001]种子词"觉醒"阶段 substitution；[FS-003]揭示链3/4步本章揭示；隐藏设定[HS-002]可揭示碎片
- 预期：C3 伏笔纪律 pass；C5 设定一致 pass；L4 张力 pass；L8 留白 pass
```

## 3. 测试执行流程（技能入库）

```
新技能入库前
  ├─ ① 无技能基准测试（TC-001/002/003 生成 + 审计，记录基准分）
  ├─ ② 有技能对比测试（激活新技能，同样生成 + 审计，记录对比分）
  ├─ ③ 质量差值分析：降幅≤5→通过；5-10→需用户确认；>10→不建议
  └─ ④ 冲突检测：与已有技能算冲突矩阵，≥0.7 标记不可同时激活
```

## 4. 测试验收标准

| 验收项 | 标准 | 说明 |
|--------|------|------|
| 质量差值 | 降幅 ≤5 分 | 不降低整体质量 |
| Blocker 问题 | 0 个 | 不引入硬逻辑错误 |
| 技能规则遵守 | 100% | 正文不违反 skill rules |
| 冲突检测 | 完成 | 冲突矩阵已计算 |
| 多场景覆盖 | ≥3 用例 | 对话/战斗/伏笔交汇 |

## 5. 回归基线（引擎变更时）

- 引擎/提示词/审计变更后，用 TC-001~003 跑"无技能"回归，与历史基线比对，防止质量倒退。
- 「优化」新增：关键一致性不变量的确定性用例可单测（`07` INV-001~008 的规则单独建测试），不依赖 LLM。
- Fact 写入协议（`05`）单测：验证 ADD-only 不覆盖、superseded 标记、source 必填、checkpoint 快照可回滚。
