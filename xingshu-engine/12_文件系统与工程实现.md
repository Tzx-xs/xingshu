# 12 · 文件系统 与 工程实现

## 1. 目录结构

```
novels/
└── {小说名}/
    ├── novel_meta.yaml              # 元数据（含 LLM 配置、进度、预算）
    ├── outlines/                    # volume/arc/chapter/scene
    ├── truth_files/                 # characters/relations/factions/locations/timeline/foreshadowing
    │   └── _facts/                  # (可选) fact 落库目录，见 `05`
    ├── settings/world_settings.md   # 双设定
    ├── chapters/                    # ch_XXX.md / _summary.md / _post_analysis.md
    ├── audits/                      # audit_ch_XXX.md / revision_ch_XXX.md
    ├── reports/                     # arc/volume 报告
    └── checkpoints/                 # 真实快照（`05`/`10` 定点回滚载体）
skill_library/
├── builtin/  user/  novels/  _meta/
```

## 2. novel_meta.yaml

```yaml
novel: {id, title, genre, language, target_audience}
creation: {total_volumes, total_chapters, chapter_word_target, pov_mode}
quality: {audit_threshold: 75, revision_max_attempts: 3, strength_default: moderate}
progress: {current_volume, current_arc, current_chapter, engine_state, last_updated}
budget:                 # 「优化」新增：显式预算表（见 §5）
  gen_tokens_per_chapter: 8000
  audit_tokens_per_chapter: 6000
  pipeline_a_b_tokens_per_chapter: 4000
  context_slice_budget: 12000
llm:
  model: "..."            # 正文生成模型
  audit_model: "..."      # 审计模型（建议独立，见 `07`）
  temperature: 0.8
```

## 3. 引擎执行流程（单章）

1. 读大纲，确认位置与任务
2. 读真相文件（按 `05` 检索协议仅取相关 fact / 切片）
3. 读技能库，按题材/注入点/触发过滤适用技能，激活≤5个、≤5000 tokens
4. 按 reveal_density 过滤设定，确定可揭示内容
5. 组装五层提示词（`08`）
6. 生成正文（流式），按场景/节拍拆子任务（`03`）
7. 执行分级审计（`07`）
8. 通过→保存正文 + 打 checkpoint；不通过→回炉（`02` §7）
9. 执行章后管线 A→B→C（`02` §3 + `05` 写入协议）
10. 输出本章摘要

## 4. 上下文管理

- **真相文件切片**：只注入与本章相关的 fact（`05` 多信号检索），不注入全量
- **前情摘要压缩**：注前 3-5 章摘要
- **认知边界过滤**：只注入视角角色的 knows+partial
- **设定按密度过滤**：未揭示隐藏设定不注入
- **进度持久化**：novel_meta.progress 持当前进度与状态，断点续作
- **压缩覆盖率校验**：压缩摘要前后比对关键实体/关系覆盖率，过低则回退压缩（`05` §8）

## 5. Token / 成本预算（本版落地关键）

「精华借鉴」LongWriter 子任务拆解 + 审计分级（`07`）+ ContextCraft 覆盖率，组合控制成本。示例预算表（可按实际模型调整）：

| 环节 | 目标 token/章 | 分级策略 |
|------|--------------|---------|
| 正文生成 | ~8000 | 按场景/节拍拆解，避免长文本质量崩塌 |
| 日常审计（P/C/I 组） | ~3000 | 确定性引擎 + 轻量 LLM 复核 |
| 关键章全量 45 维 | ~9000 | 仅战斗/转折/伏笔交汇/高潮触发 |
| 章后管线 A | ~2500 | 伏笔/演化/预期分析（LLM） |
| 章后管线 B | ~0 | 确定性规则，零 LLM（`05`） |
| 章后管线 C | ~0 | 纯记录，零 LLM |
| 幕/卷报告 + 全量校验 | 一次性 | 每幕/每卷各一次 |

> 关键结论：把章后管线 B/C 设计为**确定性零 token**，是整套系统 token 可控的根基。审计分级 + 双模型，是为阻断成本与"自证"风险的主要手段。

## 6. NLP / 工具链实现建议（原蓝图缺口补全）

原蓝图提"结构性检查做线索"但未给实现。建议按可量化程度分层：

| 检查 | 建议实现 | 说明 |
|------|---------|------|
| 句长/段落/独段比/节奏 | 规则 + 正则 | 零依赖，确定性 |
| 感官类型统计 | 词表 + 规则 | 可接受误报，仅作线索 |
| 过渡词/解释句式检测 | 正则黑名单 | 命中即标记，零误报 |
| 角色/地点/势力提及抽取 | 在名录上做实体匹配(词典) | 与真相文件实体 vs 比对 |
| 共指消解 / 关系抽取 / 情感分析 | 不依赖本地NLP，交 LLM（audit_model） | 仅存疑项送审，控制成本 |
| 语义向量检索（≥300 fact 时） | embedding 库（如 self-host）＋向量库 | 需求再引入，避免过早依赖 |

**工程原则**：能确定性化的绝不交给 LLM；LLM 只处理"需要语义理解"的存量存疑项。

## 7. 存储演化路径

| 阶段 | 存储 | 适用规模 |
|------|------|---------|
| MVP | Markdown + YAML | <200 fact |
| 中期 | 加 `_facts/` 目录 + SQLite fact 表（字段对齐 `05`） | 200–几千 |
| 大规模 | 引入向量库 + 序列快照（S3/本地） | 百万字级多卷 |

> 无论到哪一阶段，`05` 的"时效窗口 + 溯源 + superseded"字段保持一致，保证迁移平滑。

## 8. 快速启动 / 使用指南

面向最终使用（补充自原蓝图"快速启动指南"，引用已对齐本套板块编号）。

### 8.1 开始一本新小说
1. 在 `novels/` 下创建小说目录
2. 创建 `novel_meta.yaml`（元数据，格式见 `12` §2）
3. 创建 `outlines/volume_01.md`（第一卷卷纲，格式见 `03`）
4. 创建 `truth_files/` 下六个真相文件初始状态（格式见 `04`）
5. 创建 `settings/world_settings.md`（明面 + 隐藏设定，见 `06`）
6. 向引擎发出指令"开始写第1章"，引擎按 `02` 执行流程创作

### 8.2 日常创作流程
每次写作向引擎发出指令：`继续写第X章。` 引擎自动执行章级十步管线（`02` §2）并审计（`07`），完成后更新真相文件并打 checkpoint（`05`）。

### 8.3 创建自定义技能
向技能制造子系统发出：`我想创建一个技能：{描述想要的技能效果}`，子系统执行五步制造流程（`09` §5），最终由用户确认是否入库（含冲突检测与沙箱试运行，`13`）。

### 8.4 查看创作进度
向引擎发出：`查看当前小说的创作进度。` 引擎读取所有文件，汇总当前进度、质量趋势（`11`）、伏笔状态（`04`）。

> 上述指令由用户在**运行/暂停状态**（`10`）发出；读取/查看为只读操作，不改变引擎状态。
