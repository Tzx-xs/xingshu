# 04 · 真相文件 —— 事实库

> 定义六系统真相文件：小说世界的"事实数据库"，所有创作必须保持一致。
> 版本：1.0 ｜ 依赖：`01` ｜ 相关：`05`(写入协议)、`07`(交叉校验)、`11`(全量校验)

## 1. 六系统概览

| 系统 | 文件 | 内容 |
|------|------|------|
| 人物卡 | `characters.md` | 基本信息、性格、外貌、背景、能力、当前状态 |
| 社会关系卡 | `relations.md` | 角色间关系（A→B 独立边，旧记录保留） |
| 势力卡 | `factions.md` | 势力名称、宗旨、成员、层级结构 |
| 地理卡 | `locations.md` | 地点层级图、连通关系 |
| 时间流动追踪 | `timeline.md` | 时间线、事件序列、章节时间戳 |
| 伏笔规划系统 | `foreshadowing.md` | 伏笔状态、目标章节、语义演化链 |

> 每个系统的**写入协议统一见 `05`**：带时效窗口、来源溯源、不原地覆盖。

## 2. 人物卡（七维度结构）

### {角色名}（{角色ID}）
```
### ① 基础信息   别名/性别年龄/外貌/语气
### ② 性格画像   MBTI/核心特质/说话方式/个人怪癖
### ③ 能力体系   能力系/当前等级/技能列表(含解锁章节+条件)/限制/成长路径
### ④ 关系网络（主观视角） → 角色：类型/强度/态度/历史/最后更新章节
### ⑤ 心理状态（动态，每章更新） 当前状态/恐惧/渴望/秘密/内心冲突
### ⑥ 成长轨迹   当前阶段/成长目标/关键转折点
### ⑦ 认知边界（防全知穿帮） 完全知道/完全不知道/部分知道
```

**认知边界是人物卡最重要的设计** — 明确记录每个角色知道什么、不知道什么、只知道一部分。生成阶段注入视角角色的"知道+部分知道"，不注入"不知道"。多视角章节按段落切换认知边界切片。

## 3. 社会关系卡

```
### {角色A} → {角色B}
- 关系类型：师徒/敌对/恋人/同盟/...
- 详情：{描述}  ｜  起始章节 ｜  当前状态（活跃/恶化/消亡）
- 版本：v1（旧记录保留，新版本追加）
```

A→B 和 B→A 是两条独立记录。关系变化必须有"关系事件"记录（发生章节、地点、变化内容）。审计层检查：关系突变但无对应关系事件 → 标记"关系变化缺乏铺垫"。

## 4. 势力卡（五维度 + 动态）

```
### {势力名}（{势力ID}）
### ① 基本信息   类型/规模(small~huge)/影响力(1-10)/阵营
### ② 层级结构    首领/等级序列（与人物卡联动）
### ③ 目标与动机   {目标}：type(public/secret)/优先级
### ④ 势力版图    总部/控制区域/争议区域/已失去区域（引用地理卡ID）
### ⑤ 势力间关系  → 势力：类型/强度；明面关系 vs 实际关系；历史
### 实力变化（动态）  章节：事件 — 变化(influence/军事) — 版图变化
### 关键成员动态  角色(职位) — 状态 — 失去影响等级
```

**明面 vs 实际关系**：写普通角色视角注入 public_status；写间谍/高层视角注入 actual_status，防止角色知道不该知道的势力关系。

**版图/成员联动**：势力控制区域引用地理卡 ID；层级持有者引用角色 ID。地理被毁 → 势力控制区自动受影响；角色能力升级 → 审计层检查职位是否应提升。

## 5. 地理卡

```
### {地点名}（{地理卡ID}）
### 基本信息   类型/上级地点/下级地点/描述
### 内部布局   区域
### 旅行信息矩阵  → 地点：方式/耗时/路线
### 环境特征   气候/地形/特殊
### 地点状态变化（动态）  章节：变化 — 新状态
### 角色到访记录  角色：章节
### 发生在此地点的事件  章节：事件
```

**旅行时间矩阵**：审计检查——角色位置须满足旅行耗时，否则标记时间线矛盾。
**地点状态变化**：审计检查旧状态被引用的矛盾（如外门已毁却写"整洁训练场"）。

## 6. 时间流动追踪（四维度）

```
### ① 当前叙事时间锚点  故事内时间/当前章节/季节/天气/时段
### ② 多线时间追踪  主线/暗线/回忆线（含交汇点）
### ③ 角色时间感知  感知时间 vs 实际时间（防主观时间穿帮）
### ④ 并行事件追踪  时间窗口：地点/事件/角色/章节/读者是否知晓
### 时间跨度记录  区间 → 跨度 + 关键里程碑
### 时间一致性约束（审计自动检查）  旅行/修炼周期/季节/日夜/并行不冲突
```

```
### 语义演化链

```

## 8. 真相文件维护规则

1. 章后管线-B 每章必须更新真相文件
2. 旧记录保留不覆盖（新版本追加，保留关系演变历史）
3. 卷间全量校验（见 `11`）
4. 创作时只读：生成正文阶段只读不改，修改只在章后管线-B
5. 「精华借鉴」所有写入必须带**来源**与**时效**（见 `05`），以满足审计溯源与定点回滚

## 9. 六系统交叉校验（审计层）

以"第27章林远在训练场与周宁对练"为例，同时查：人物卡（心理状态是否支持）、社会关系卡（关系强度是否支持动作）、势力卡（区域权限）、地理卡（当前位置/移动耗时）、时间流动（时段是否允许）、伏笔规划（是否有需推进的伏笔）。详见 `07`。
